# 七步财务分析法 - Agent 生成 SOP（通用版 v2）

> **本文件用途**：通用 SOP。A股公司任何公司给定 3 张财务报表 CSV，按本 SOP 生成两份文件。
>
> 适用场景：上市公司年报、东方财富/同花顺/Wind 导出的合并报表，N 年（不限年数）。
>
> 不适用：银行/保险/证券（科目结构差异大）、母公司报表。

---

## 🚀 速查卡（Quick Reference）

> Agent 执行前先扫这一页，关键信息全在这里。

### 输出文件
- `output.csv` — 主数据（按 §3 格式严格生成）
- `data_status.md` — 数据完整性说明

### 7 个步骤标题（固定，不要改）
```
第一步：看营收数据 (建立基本面轮廓，评估盈利质量)
第二步：看成本费用构成 (理解盈利结构，识别效率变化)
第三步：看增长 (把握核心趋势，评估未来潜力)
第四步：看业务构成 (拆解收入引擎，定位驱动力来源)
第五步：看资产负债 (评估资产效率和财务风险)
第六步：看投入产出 (核心视角，理解商业模式本质)
第七步：看收益率 (综合评估股东回报和资产效率)
```

### 数据行结构（13 列）
```
<指标名>, <最新年值>, <次新年值>, ..., <最旧年值>, , ,
 ^         ^                                                          ^
 第1列     第2列到第11列（N个年份值）                                 第12-13列空
```

### 核心算法速记
| 场景 | 公式 |
|---|---|
| 平均指标（行 i，从 0 开始） | `i < N-1` 时：`avg[i] = (v[i] + v[i+1]) / 2`<br>`i = N-1`（最右列）：`avg[N-1] = v[N-1] / 2` |
| 增长率（行 i，从 0 开始） | `i < N-1` 时：`(v[i] - v[i+1]) / v[i+1]`<br>`i = N-1`（最右列）：`除数为零。` |
| 空值处理 | 源 CSV 空 → 当作 `0`（数字字段）；文字字段留空 |
| 时间方向 | 从左到右 = 从新到旧 |

### 硬约束 vs 自由度（优先级）
**§3 输出格式硬约束 > §6 自由度建议**。自由度仅在 §3 未明确规定时适用。

### 缺数据怎么办
- 数字指标 → 写 `0`
- 字符串指标 → 留空
- 整段缺失（业务构成、员工）→ 不写标题行、不写指标行
- **绝不凭空捏造**

## 0. 任务目标

**输入**：3 张 CSV，文件名按惯例命名为 `<公司名>利润表.csv`、`<公司名>资产负债表.csv`、`<公司名>现金流量表.csv`（Agent 应根据用户提供的实际文件名识别）。

**输出**：在脚本所在目录生成两份文件：
- `output.csv` — 主数据文件
- `data_status.md` — 数据完整性说明

**核心约束**：CSV 必须严格按 §3 格式生成。指标如何从源 CSV 取、用什么公式，由本 SOP 的语义描述决定，**让 LLM 自主理解和识别**。

## 1. 源数据识别原则

⚠️ **核心原则**：**用语义理解找数据，不用行号匹配**。

### 1.1 通用识别流程

源 CSV 的列头一般形如：
```
,<最新年>年年报,<次新年>年年报,...,<最旧年>年年报,,,
```

例如牧原股份的源 CSV（2016-2025）：`,2025年年报,2024年年报,...,2016年年报,,,`

Agent 应：
1. **从表头自动读出年份范围**（不要假设是 2016-2025，可能是任意 N 年）
2. **识别列方向**：时间从左到右 = 从新到旧（最新年份在最左列）
3. **从科目名识别语义**（见 §1.2 关键词表）
4. **科目名做归一化处理**（见 §1.3）

### 1.2.1 ⚠️ 取数防坑硬规则（同名空行 / 小计行陷阱）

> **这是本 SOP 最容易翻车的地方，也是跨公司复用的头号坑。**
> 东方财富/同花顺导出的 CSV 普遍存在「同名空的小计行 + 有值的合计行」结构：
> 例如 `利息收入(元)` **全空**，而 `减：利息收入(元)` **有值**；`长期应付款(元)` **全空**，而 `长期应付款(合计)(元)` **有值**。
> 任何"遇到第一个匹配就返回"的取数逻辑都会取到空行，导致**金融利润、有息债务等整列算错**——而且不会报错，极难发现。

**Agent 取数时必须遵守以下顺序（脚本 `g()` 已实现，手工取数同理）：**

1. **收集所有候选**：凡科目名精确等于关键词、或包含关键词的行，都列入候选（**不要见一个就返回**）。
2. **跳过全空行**：10 个年份值全部为 0 / 空的行直接剔除（它们是小计占位行，不是数据）。
3. **优先级排序**（命中多个有值行时）：
   - `(合计)` 行最高（如 `长期应付款(合计)`，是合并后的完整值）→ 优先
   - `减：` 字头行次高（如 `减：利息收入`，是带减号的真实值行）→ 优先
   - `其中：` 子项最低（如 `其中：xxx`）→ 避开
   - 含「总收入」的口径（如 `营业总收入`）略低于标准口径（如 `营业收入`）→ 主业口径优先
4. **歧义必须报警**：若仍有 ≥2 个不同名、有值的候选且优先级相同，**必须打印警告并记入 `data_status.md` 的「⚠️ 校验异常」**，绝不静默取第一个。


### 1.3 科目名归一化处理

源 CSV 的科目名可能有以下"噪音"，Agent 必须先归一化再匹配：

```python
def normalize(name: str) -> str:
    name = name.replace('　', '')        # 去全角空格 (U+3000)
    name = name.replace(' ', '')          # 去半角空格
    name = name.replace('\t', '')         # 去 tab
    if name.startswith('其中：'):           # 剥离子项前缀
        name = name[3:]
    return name.strip()
```

### 1.4 找不到的科目怎么办

直接跳过该指标：
- 数字字段写 `0`
- 文字字段留空
- 在 `data_status.md` 中记录"该科目在源报表中未披露"

### 1.5 特殊公司差异

不同行业可能有特殊科目：
- **养殖业**：生产性生物资产
- **房地产**：投资性房地产占大头
- **互联网**：商誉、长期股权投资可能较多
- **银行业**：完全不同的科目体系（本 SOP 不适用）

Agent 不需要为这些特殊科目写特殊规则——按语义分类即可（详见 §2.5）。

## 2. 七步分析法框架

> 七步法来自饶刚《简明财务分析》。这是公认的方法论，所有公司通用。

每一步产出几类指标，**指标名**用以下标准命名（用户后续脚本/分析会引用这些名字，不要随意改动）。

### 第一步：营收数据 — 建立基本面轮廓

**业务意图**：看公司"长多大、赚多少、赚的是不是真钱"。

| 指标 | 公式 | 数据来源 | 业务含义 |
|---|---|---|---|
| 营业收入 | 直接读取 | 利润表 | 公司主营业务的总规模 |
| 归母净利润 | 直接读取 | 利润表 | 股东实际能分到的利润（扣除少数股东） |
| 净利润率 | 净利润 / 营业收入 | 派生 | 综合盈利能力 |
| 扣非净利润 | 直接读取 | 利润表（如有） | 主营业务真实盈利（剔除非经常性损益） |
| 经营活动净现金流 | 直接读取 | 现金流量表 | 业务"真金白银"的流入 |
| 自由现金流 (FCF) | OCF - CAPEX | 派生 | 扣掉扩产投入后剩的钱 |
| 资本开支 (CAPEX) | 直接读取 | 现金流量表 | 当期扩产花了多少钱 |
| 扣非净利润/净利润 | 派生比率 | — | 衡量利润"纯度"（接近 1 = 主业利润；偏离 1 = 有非经常性项目） |
| 经营净现金流/归母净利润 | 派生比率 | — | 利润的现金含量（>1 健康，<1 警惕） |
| 金融利润 | 投资收益 + 公允价值变动 + 利息收入 | 利润表 | 投资活动赚的钱（用于剥离主业利润） |
| 经营利润 | 归母净利润 - 金融利润 | 派生 | 主业真实盈利（剔除投资赚的钱） |
| 经营利润/归母净利润 | 派生比率 | — | 主业利润占比（接近 1 = 主业为主） |

**预测部分**（如有用户提供）：
- 营业收入预测（未来 3 年）
- 归母净利润预测

### 第二步：成本费用构成 — 理解盈利结构

**业务意图**：看公司的"成本基因"——是制造业、研发驱动、还是销售驱动？

| 指标 | 公式 | 数据来源 | 业务含义 |
|---|---|---|---|
| 毛利率 | (营业收入 - 营业成本) / 营业收入 | 派生 | 产品/服务的"溢价能力" |
| 净利率 | 净利润 / 营业收入 | 派生 | 最终利润率（综合考虑费用、税收等） |
| 研发费用 | 直接读取 | 利润表 | 创新投入 |
| 管理费用 | 直接读取 | 利润表 | 行政成本 |
| 销售费用 | 直接读取 | 利润表 | 渠道/营销投入 |
| 财务费用 | 直接读取 | 利润表 | 融资成本 |
| 4 个费用率 | 各项费用 / 营业收入 | 派生 | 看哪类费用占比高 |
| 毛利率-净利率 | 派生 | 派生 | 反映"非直接成本"（费用、税收等）占总毛利的份额 |

**注意**：如果该公司不披露研发费用（例如传统行业），该指标写 0。

### 第三步：增长 — 把握趋势

**业务意图**：看公司在扩张还是收缩，增长质量如何。

| 指标 | 公式 | 业务含义 |
|---|---|---|
| 营收增长率 | (本期 - 上期) / 上期 | 规模扩张速度 |
| 归母净利润增长率 | 同上 | 盈利增长（可能与营收背离，提示利润率变化） |
| 扣非净利润增长率 | 同上 | 主业真实盈利增长 |

**边界**：最旧的一年（最右列）没有上一年数据，写 `除数为零。`（固定字符串）。

**预测部分**（如用户提供了预测值）：
- 券商预测营收增长率 = (预测1年营收 - 最新1年营收) / 最新1年营收，依此类推
- 券商预测归母净利润增长率 = 同上

### 第四步：业务构成 — 拆解收入引擎（⚠️ 通常需要外部数据）

**业务意图**：看公司的"多元化程度"和"核心业务护城河"。

⚠️ 三大报表**不直接包含**分业务收入数据（除非报表附注）。

**数据来源**：年报"主营业务分行业/分产品"章节，通常需要用户提供独立的分业务 CSV。

**如果用户未提供**：整段跳过（不写标题行、不写指标行），并在 `data_status.md` 中记录。

**如果用户提供了**：按以下结构生成。指标名可按用户实际业务调整（如"养殖/屠宰"对养殖业，"手机/IoT"对制造业）：

```
[各业务收入, 一般 3-6 个]
减:内部抵消
所有营收合计 (= 各业务合计，应等于利润表营业收入)
[各业务占比]
[核心业务的成本与毛利率]
```

### 第五步：资产负债 — 评估效率与风险

**业务意图**：看公司"资产怎么配置、杠杆有多高、债务结构如何"。

基础项：

| 指标 | 数据来源 | 业务含义 |
|---|---|---|
| 流动资产、货币资金、存货 | 资产负债表 | 短期可变现资产 |
| 非流动资产、总资产 | 资产负债表 | 长期资产 + 总盘子 |
| 归母净资产 | 资产负债表 | 股东权益底子 |
| 无息债务（应付+预收+合同负债类） | 资产负债表 | 占用上下游资金的负债（无成本） |
| 有息债务（短期借款+长期借款+应付债券+长期应付款类） | 资产负债表 | 需付息的真实负债 |
| 资产负债率 | 派生 | 总体杠杆水平 |

#### ⭐ 经营/金融资产/负债划分（核心方法论）

这是一个**通用框架**，所有公司都按"经营 vs 金融"两分法看资产负债。判断依据是**科目名的语义**，不是行号。

| 概念 | 语义判断标准 |
|---|---|
| **金融资产** | 不直接参与主营业务的、用来投资/获利的资产。判断词：投资、交易性、可供出售、衍生、长期股权、其他权益工具 |
| **金融负债** | 主要为融资目的的负债。判断词：借款、债券、租赁负债、应付股利、衍生金融负债、交易性金融负债 |
| **经营性负债** | 与日常经营相关的负债。判断词：应付、预收、合同负债、应付薪酬、应交税费 |
| **经营资产** | 公式思路：`经营资产 ≈ 总资产 - 金融资产 - 可供出售金融资产`（应收股利已计入金融资产，不再单独加回） |
| **净金融资产** | 金融资产 - 金融负债 | 衡量企业"净欠"或"净借" |
| **净营运资产** | 经营资产 - 经营性负债 | 日常运营占用的净资金 |
| **净经营资产收益率** | 第一步的"经营利润" / 净营运资产 | 主业的真实回报率（剥离金融业务） |

**📚 参考案例（牧原股份）**：

这是 Agent 用来理解上述标准的示例，**不是强制公式**。不同公司按其行业特性灵活处理：

```
# 牧原股份（养殖业）
金融资产 = 交易性金融资产 + 长期股权投资 + 其他权益工具投资 + 投资性房地产 + 应收股利
金融负债 = 短期借款 + 交易性金融负债 + 应付股利 + 应付债券
          + 一年内到期的非流动负债 + 租赁负债 + 长期应付款 + 递延收益
          （注：牧原报表中应付债券记为融资租赁性质，可从此处移除；标准口径默认含应付债券）
经营性负债 = 应付票据应付账款 + 预收款项 + 合同负债 + 应付职工薪酬
            + 应交税费 + 其他应付款合计 + 其他流动负债
经营资产 = 总资产 - 金融资产 - 可供出售金融资产
         （注：可供出售金融资产虽叫"金融"，但分类上不计入金融资产，故从总资产中扣除；
          应收股利已计入金融资产，故不再单独加回经营资产——保持"总资产 - 金融资产 - 可供出售金融资产"即可）
```

**📖 参考其他行业的可能差异**：

- **银行业**：金融资产负债占比极高，几乎没有"经营性"概念，可能不适用本框架
- **重资产制造业（如钢铁）**：经营资产主要是固定资产+存货
- **互联网/SaaS**：可能有较多"使用权资产"、"商誉"（收购形成），属于经营资产
- **周期性行业（养殖、化工）**：存货占比高，需重点关注存货跌价

**Agent 处理建议**：
1. 先按上面的语义标准对源 CSV 科目分类
2. 参考牧原案例理解，但根据该公司实际科目灵活调整
3. 在 `data_status.md` 中列出**最终采用了哪些科目**以及分类理由

**关键输出**：
```
经营资产（带说明性注释行，可选）
经营性负债（带说明性注释行，可选）
净营运资产 = 经营资产 - 经营性负债
金融资产（带说明性注释行，可选）
```

### 第六步：投入产出 — 理解商业模式本质

**业务意图**：看公司"占用多少资源、产生多少周转、效率如何"。

基础项（基于资产负债表 + 利润表）：

| 指标 | 公式 | 业务含义 |
|---|---|---|
| 营运资本期末 WC | (应收账款 + 应收票据 + 预付账款 + 存货) - (应付账款 + 应付票据 + 预收账款 + 合同负债) | 日常运营占用的净流动资金 |
| 营运资本期初 WC | 上一年期末值 | — |
| ΔWC | 期末 - 期初 | 运营资金变化（正=占用增加） |
| 1元收入需要的WC | WC / 营业收入 | 资金效率（越小越好） |
| 各项占收入比 | (应收/预付/存货/应付/预收/合同负债) / 营业收入 | 资产负债结构相对收入的比重 |
| 固定资产合计 | 固定资产 + 在建工程 | 广义固定资产 |
| 长期资产合计 | 固定资产 + 无形资产 + 使用权资产 + 商誉 + 长期待摊 | 广义长期资产 |
| 1元收入需要的固定资产/长期资产 | 派生 | 重资产程度（越大越"重"） |
| 人均收入/利润/薪酬 | 营业收入/归母净利润/(应付职工薪酬期初-期末+支付给职工现金) / 员工总数 | 人效指标 |

**员工数据**（⚠️ 通常需要外部数据）：
- 员工总人数、分工种人数（生产、销售、财务、技术、研发、行政）
- 来源：年报"员工情况"章节
- 若未提供：员工总数及人均指标全部跳过

### 第七步：收益率 — 综合评估股东回报

**业务意图**：综合看"股东能赚多少、回报率有多高"。

⭐ **平均指标算法**（关键，容易写错）：
```
对于某指标的 N 个年度数据 [v_n, v_{n-1}, ..., v_1]（左到右：最新到最旧）：
- 对第 i 列（0-indexed），如果 i < N-1：avg[i] = (v[i] + v[i+1]) / 2
- 对最右列（i = N-1，即最旧年）：avg[N-1] = v[N-1] / 2
```

⚠️ **常见错误**：
- ❌ 把最左列的 avg 设成 None（错！应该是 (v最新 + v次新) / 2）
- ❌ 把最右列的 avg 算成 (v次旧 + v最旧) / 2（错！应该是 v最旧 / 2）

基础指标：

| 指标 | 公式 | 业务含义 |
|---|---|---|
| ROA | 净利润 / 平均总资产 | 资产回报率（总资产收益率） |
| ROIC | 净利润 / (股东权益合计 + 有息债务) | 投入资本回报率（比 ROE 更严谨） |
| ROE | 净利润 / 平均股东权益合计 | 净资产回报率（股东最关心的指标） |
| 销售净利率 | 净利润 / 营业收入 | 利润率 |
| 总资产周转率 | 营业收入 / 平均总资产 | 资产周转效率 |
| 权益乘数 | 平均总资产 / 平均股东权益合计 | 财务杠杆 |

平均类基础数据：

| 指标 |
|---|
| 总资产、平均总资产 |
| 流动资产、平均流动资产 |
| 固定资产、平均固定资产 |
| 存货、平均存货 |
| 营运资本、平均营运资本 |
| 应收、平均应收（应收 = 应收账款 + 应收票据） |
| 归母净资产、平均归母净资产 |

周转天数：

| 指标 | 公式 | 业务含义 |
|---|---|---|
| 总资产周转天数 | 365 / 总资产周转率 | 资产周转一圈要多少天 |
| 流动资产周转天数 | 365 / (营业收入 / 平均流动资产) | 流动资产周转效率 |
| WC周转天数 | 365 / (营业收入 / 平均WC) | 营运资本周转效率 |
| 应收账款周转天数 | 365 / (营业收入 / 平均应收) | 收钱速度 |
| 存货周转天数 | 365 / (营业收入 / 平均存货) | 卖货速度 |
| 固定资产周转天数 | 365 / (营业收入 / 平均固定资产) | 固定资产产出效率 |

### Step 1：加载源 CSV

```python
import csv

def load_csv(path):
    """加载 CSV，提取年份列范围和科目-值映射"""
    with open(path, 'r', encoding='utf-8-sig') as f:
        reader = csv.reader(f)
        rows = list(reader)
    headers = [h.strip() for h in rows[0]]
    
    # 识别年份列
    year_cols = {}  # year -> col_index
    for i, h in enumerate(headers):
        if h.endswith('年年报'):
            year = h.replace('年年报', '')
            year_cols[year] = i
    
    # 提取数据
    data = {}  # {科目名: {年份: 值}}
    for row in rows[1:]:
        if not row or not row[0].strip():
            continue
        name = normalize(row[0])  # 归一化
        if name == '数据来源：妙想Choice':
            continue
        vals = {}
        for year, idx in year_cols.items():
            v = row[idx].strip() if idx < len(row) else ''
            vals[year] = float(v) if v else 0.0  # 空值当 0
        data[name] = vals
    return data, sorted(year_cols.keys(), reverse=True)  # 年份从新到旧
```

### Step 2：归一化科目名

```python
def normalize(name: str) -> str:
    name = name.replace('　', '')        # 去全角空格 (U+3000)
    name = name.replace(' ', '')          # 去半角空格
    name = name.replace('\t', '')         # 去 tab
    if name.startswith('其中：'):           # 剥离子项前缀
        name = name[3:]
    return name.strip()
```

### Step 3：抽取基础数据

按 §1.2 关键词表匹配科目，逐年取出。**必须遵循 §1.2.1 的取数防坑硬规则**（跳过空行、优先级、歧义报警）：

```python
def prio(name: str) -> int:
    """候选行优先级：越高越优先（规避同名空行/小计行陷阱）"""
    s = 0
    if '(合计)' in name:   s += 100   # 合并完整行优先
    if '减：' in name:     s += 50    # 财务费用明细真实值行优先
    if name.startswith('其中：'): s -= 100  # 子项避开
    if '总收入' in name:   s -= 10    # 主业口径优先
    return s

def get_value(data, metric_keywords, year):
    """在 data 中查找匹配 metric_keywords 的科目，规避空行陷阱"""
    cands = []
    for name, vals in data.items():
        score = 0
        for kw in metric_keywords:
            if name == kw:            score = max(score, 3)  # 精确匹配
            elif kw in name:          score = max(score, 1)  # 子串匹配
        if score:
            cands.append((name, vals, score))
    if not cands:
        return 0
    # 跳过全空行（小计/占位空行）
    non_empty = [c for c in cands if any(abs(v) > 1e-9 for v in c[1].values())]
    pool = non_empty if non_empty else cands
    pool.sort(key=lambda c: (prio(c[0]), c[2]), reverse=True)
    best = pool[0]
    # 歧义报警：最高优先级并列且不同名
    top = [c for c in pool if prio(c[0]) == prio(best[0]) and c[2] == best[2]]
    if len(top) > 1:
        print(f'⚠️ 取数歧义 {metric_keywords} -> 候选: {top}，已取 {best[0]}')
    return best[1].get(year, 0)
```

```python
import csv

def write_csv(rows, output_path):
    """rows: [(row_type, content)] 列表
    row_type: 'header' | 'title' | 'data' | 'pred_header' | 'pred_data'"""
    with open(output_path, 'w', encoding='utf-8', newline='') as f:
        writer = csv.writer(f)
        for row_type, content in rows:
            if row_type == 'header':
                writer.writerow(content)
            elif row_type == 'title':
                writer.writerow([content] + [''] * 12)
            elif row_type == 'data':
                # content: (metric_name, [v_year1, v_year2, ...])
                metric, values = content
                writer.writerow([metric] + values + ['', ''])
            elif row_type == 'pred_header':
                writer.writerow([''] + content + [''] * 9)
            elif row_type == 'pred_data':
                metric, values = content
                writer.writerow([metric] + values + [''] * 9)
```

| 科目名差异（如"营业总收入" vs "营业收入"） | 都视为营业收入，标准化命名 |
| 行业特殊科目（金融业的"客户存款"） | 按语义判断归属（金融/经营/不适用） |
| 报表附注信息（如分业务、员工） | 用户未提供则跳过 |
| 缺少某些项目导致公式不完整 | 跳过该指标，data_status 中说明 |
| 年份数与示例不同（如只有 5 年或 15 年） | 按实际年份数生成列 |
| 金融资产负债的具体科目 | 按 §2.5 语义标准分类，不强求与牧原案例完全一致 |

### 6.2 硬约束优先级（务必记住）

```
§3 输出格式硬约束 >> §6 自由度建议
```

**绝对不能自由发挥的**：
- 输出文件必须是 `output.csv` 和 `data_status.md`
- 7 个步骤标题必须完全一致（见 §3.5）
- 数据行必须是 13 列
- 时间方向必须从新到旧
- 最右列增长率必须写 `除数为零。`
- 缺数据不编造

## 8. 陷阱汇总（FAQ）

### 🚫 常见错误 1：行号匹配
**症状**：硬编码"第 12 行 = 应收账款"，换家公司就报错。
**正解**：用 §1.2 关键词表匹配，不用行号。

### 🚫 常见错误 2：年份写死
**症状**：假设源 CSV 一定是 2016-2025，2028 年跑就崩。
**正解**：从表头自动识别年份。

### 🚫 常见错误 3：平均指标方向反了
**症状**：`avg[最右] = (v次旧 + v最旧) / 2`，导致 2016 年的"平均"用了 2017 的数据。
**正解**：`avg[最右] = v最旧 / 2`。

### 🚫 常见错误 4：增长率缺失判断
**症状**：2016 年的增长率写成 `None` 或 `0`，导致后续计算错误。
**正解**：写固定字符串 `除数为零。`。

### 🚫 常见错误 5：把"营业总收入"和"营业收入"当成两个指标
**症状**：同时出现两行，导致重复计入。
**正解**：归一化为同一指标名（见 §1.2）。

### 🚫 常见错误 6：全角空格未处理
**症状**：源 CSV 用 U+3000 缩进，Agent 用 `.strip()` 后仍带空格，匹配失败。
**正解**：先 `.replace('　', '')` 再匹配。

### 🚫 常见错误 7：行内换行符未处理
**症状**：如"购建固定资产、无形资产和\n其他长期资产..."，匹配不到。
**正解**：关键词匹配用 `in` 而不是 `==`。

### 🚫 常见错误 8：CSV 含 `\n` 的指标名没加引号
**症状**：metric 名内嵌 `\n`，直接 `,` join 会切分行。
**正解**：用 `csv.writer` 自动加引号。

### 🚫 常见错误 9：把"减：利息收入"取反
**症状**：金融利润算错，因为多取了一次负号。
**正解**：`利息收入 = "减：利息收入" 行的原值`（这本身就是负的利息收入，但我们要加它）。或者从"财务费用"行提取。

### 🚫 常见错误 10：第四步没数据时仍写标题
**症状**：用户没提供业务数据，CSV 里有"第四步：看业务构成..."但下面没数据，看着别扭。
**正解**：整段跳过（包括标题行）。

### 🚫 常见错误 11：同名空行/小计行陷阱（最隐蔽，无报错）
**症状**：金融利润、有息债务、长期应付款等**整列偏小或偏 0**，但脚本不报错、资产平衡也通过，肉眼极难发现。根因是取数函数命中了同名的**全空小计行**（如 `利息收入(元)` 空行而非 `减：利息收入(元)`；`长期应付款(元)` 空行而非 `长期应付款(合计)(元)`）。
**正解**：严格按 §1.2.1 取数防坑硬规则——**收集全部候选 → 跳过全空行 → 按 `(合计)`/`减：` 优先级取 → 歧义报警**。脚本 `g()` 已内置，换公司直接复用即可。

## 🧩 可选增强模块（v2.1 新增，不改变主表结构）

> 以下两项为**可选增强**：主表 `output.csv`（历史实际 13 列 × N 年）保持不变，增强内容通过**注入行 / 伴侣文件**实现，确保可回归、可叠加。

### 增强 A：第六步 员工构成注入（需用户提供员工 XLS/CSV）

- **何时做**：用户额外提供"员工构成"文件（常见来源：妙想Choice / 年报"员工情况"）时。
- **注入位置**：第六步标题行之后，按专业 + 人均派生 + 按学历 分组。
- **关键坑（必读）**：
  1. **技术 = 研发（同源，禁止相加）**：部分源文件中 `技术人员` 与 `研发人员` 数值完全相等（同源口径）。按职能合计时**只取其一**（推荐取"技术人员"），否则重复计数导致职工总数无法闭合。
  2. **隐藏的 2016 列**：老格式 `.xls` 常把 2016-12-31 藏在末列（如 col12），且夹带半年报列（如 2024-06-30 / 2017-06-30）需跳过。注入前务必逐列核对表头，避免漏读/错位。
  3. **人均指标派生**：人均营业收入 = 营业收入 ÷ 职工总数；人均归母净利润 = 归母净利润 ÷ 职工总数。有职工总数即可自动算，补齐"人均"维度。
- **校验**：职能合计（生产+销售+财务+技术+行政）与学历合计（博士+硕士+本科+大专）应分别 = 职工总数。

### 增强 B：前瞻一致预期（营收 / 归母净利润预测，需外部一致预期源）

- **何时做**：用户要求补充"未来预测"维度时。
- **核心方法**：所谓"搜集所有券商研报"实际等价于**机构一致预期（Consensus）**——即对全市场数十家券商盈利模型的汇总。以一致预期接口（如 westock `data_consensus`）为主源，并抽查若干个股研报展示**离散度**（单家预测跨度可达 ±18%，故必须取中枢而非单家）。
- **主表隔离原则**：`output.csv` 严守历史实际结构，**不混入未来年份**。前瞻数据独立成伴侣文件 `forecast_consensus.csv`（列：指标 / 2025A / 2026E / 2027E / 2028E / 说明），并在 `data_status.md` 设「一致预期（前瞻）」专节说明来源、离散度、前瞻校验与口径。
- **口径约定**：预测净利默认取**归母净利润**（归属母公司股东净利润），与第一步"归母净利润"前瞻对齐；如需扣非口径另行说明。
- **外推标注**：2028E 等多为外推值（参与机构数=0），需明确标注"非机构共识，仅作趋势参考"。
- **前瞻性声明**：一致预期是券商模型假设汇总，非承诺，不构成投资建议。

> 设计哲学：七步法的骨架是"历史实际"，增强模块是"未来预期"与"人员投入"，二者分置可同时获得**纯净可回归的主表**与**完整的分析闭环**。
