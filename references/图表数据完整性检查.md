# 图表数据完整性检查清单（v7.1 · 图表坑位实录）

> **来源**：2026-08-18 美的集团七步财报分析报告实战，三个图表坑连续踩中。
> **定位**：HTML 报告生成后、交付前，对 16 张图逐图做数据完整性检查。这是「生成后验证」的硬门禁，**不许跳过**。
> **核心教训**：图表"容器在但没内容/内容错位"往往不是 Chart.js 的锅，是**数据源（output.csv / build_report_data.py）的坑**——先查数据，再查代码。

## 一、三类高频图表坑

### 坑 1：数据集全 null → 图表空白（chart 有容器无内容）

**症状**：某图标题/坐标轴正常，但图区空白（截图：第 3 步 CAGR 对比图下方一片空白）。

**根因**：`build_forecast.py` 没跑 / 预测列没注入 output.csv → 图里「预期 CAGR」数据集 `data:[null, null]`，Chart.js 对 null 不画柱子。

**预防**：
1. 七步 skill 若用「历史 vs 预期」对比图，Phase 0 必须跑通 `build_forecast.py`（产出 forecast 行），或在装配阶段补机构一致预期值。
2. 装配后**逐图扫描 `data:[…]` 是否含 `null, null` 或全 null 数据集**。

**修复模板**：
```js
// 预期数据缺失时：要么删掉该数据集，要么填机构一致预期值并改图例标签
{label:'机构一致预期 CAGR（2026E–2028E）',data:[8.2, 9.5],backgroundColor:window.__c.green}
// 预期值参考 Wind/同花顺一致预期区间，属公开可验证数据；不可编造离谱值
```

### 坑 2：业务分类跨年变更 → 堆叠图错位空白段

**症状**：图7（收入结构）/ 图8（分板块毛利率）中间出现**大片空白**（截图：第 4 步两张图）。

**根因**：公司中途改披露口径（美的 2024 起「暖通+消费电器」并为「智能家居业务」、「机器人+商业」并为「商业及工业解决方案」），旧代码把 **11 个业务名混画 10 年**，每业务只在自己的年份窗口有值（其他年份 null）→ 堆叠面积图遇 null 出空白段。

**预防（必查）**：
1. **先确认业务口径是否变更**：`按产品(项目)分类` CSV 中，看是否有业务名在某年份后消失/新增（如「智能家居业务」2024 起出现、「暖通空调」2024 起消失）。
2. **口径有变更 → 必须分段画图**，禁止单张堆叠面积图跨全时段。
   - 2017–2023：细分段（4-5 类）
   - 2024–2025：合并段（3 类）
3. 图例给新口径标「(合并)」后缀，折线用虚线+方块点区分合并段。

**修复模板（图7 水平堆叠条形，按两段时间窗口）**：
```js
window.__reg('chart7',(function(){
  var yrs = ['2017','2018','2019','2020','2021','2022','2023','2024','2025'];
  var ac2023 = [39.61, 42.13, 42.99, 42.65, 41.58, 43.80, 43.31, null, null]; // 暖通空调
  var sm2025 = [null, null, null, null, null, null, null, 66.20, 65.71];    // 智能家居(合并)
  return {type:'bar',
    data:{labels:yrs,datasets:[
      {label:'暖通空调',data:ac2023,backgroundColor:'#635bff',stack:'a'},
      {label:'智能家居业务(合并)',data:sm2025,backgroundColor:'#635bff',stack:'a'}
      // …其余业务同理
    ]},
    options:{indexAxis:'y',responsive:true,maintainAspectRatio:false,
      scales:{x:{stacked:true,title:{display:true,text:'收入占比（%）'},ticks:{callback:v=>v+'%'},max:100},
              y:{stacked:true,title:{display:true,text:'年份'}}}}};
})());
```

**修复模板（图8 折线，合并段虚线+方块点）**：
```js
{label:'智能家居业务(合并)',data:smG,borderColor:'#635bff',
  borderDash:[6,4],backgroundColor:'transparent',fill:false,tension:0,
  pointRadius:6,pointStyle:'rectRot',borderWidth:3}
// 细分段用实线圆点，合并段用虚线方块点，视觉区分口径拐点
```

### 坑 3：引用了未加载的 Chart.js 插件 → 整个图表 JS 报错

**症状**：想画"口径变更"分割虚线，用了 `annotation:{annotations:{…}}` 配置，但 HTML 没引入 `chartjs-plugin-annotation` → JS 报错，可能拖垮该图甚至整页。

**预防**：
1. **用了哪个 Chart.js 插件，必须先确认 HTML 里加载了**（`assets/` 或 CDN `<script src>`）。
2. 模板只内置 `chartjs-plugin-datalabels`，**没有 annotation 插件**——需要分割线时，改用 CSS 叠加 / 图例 `(合并)` 标注 / 虚线数据点表达，不要引 annotation。

**替代方案（不用插件画分割线）**：
- 图例文字标注（最稳）：新口径数据集 label 加「(合并)」后缀。
- 折线样式区分：合并段 `borderDash:[6,4]` + `pointStyle:'rectRot'`。
- 若一定要分割线：在 chart 容器上用绝对定位 CSS 画一根竖线（不影响 JS）。

**通用扫描命令**：
```bash

grep -oE 'data:\[\s*\]' report.html | head
# 3. 找未加载插件的引用
grep -n 'annotation\|chartjs-plugin' report.html
```

## 三、JS 语法验证（HTML 不能直接 node --check）

HTML 文件不能直接 `node --check`。用 Python 提取全部 `<script>` 块再逐个 check：

```bash
python3 -c "
import re, pathlib, subprocess, sys
html = pathlib.Path('report.html').read_text(encoding='utf-8')
scripts = re.findall(r'<script[^>]*>(.*?)</script>', html, re.DOTALL)
bad = 0
for i, s in enumerate(scripts):
    p = f'/tmp/_chk_{i}.js'
    pathlib.Path(p).write_text(s, encoding='utf-8')
    r = subprocess.run(['node', '--check', p], capture_output=True, text=True)
    if r.returncode != 0:
        bad += 1
        print(f'Script #{i} 语法错误: {r.stderr[:300]}')
print(f'{len(scripts)} 个 script 块，{bad} 个错误')
sys.exit(1 if bad else 0)
"
```

**注意**：该命令校验的是提取出的 JS 片段本身——模板里 JS 引用 DOM 变量（`window.__reg`、`window.__c`、`window.__years`）不报错是正常的（非运行时检查）。
