# 七步财报分析 · 联网核实与来源可核查规范（v2.1.4）

> 适用范围：`render_report.py` 产出的最终 HTML、`build_report_data.py` 的 `content.json`、Phase 0 的 `forecast_input.csv`。
> 配套：`SKILL.md` §1.4（可信度分级）/ §1.11-b（一致预期取数铁律）/ §19.3（content.json）/ §19.5（门禁）；门禁实现见 `scripts/check_html.py`，网络验活见 `scripts/verify_links.py`。
> 一句话：把「能不能查出这个数字」从人工自觉，变成字段、门禁、脚本三处可机械证明。

---

## 一、为什么

`§1.11-b` 已规定「一致预期必须本轮联网取数」，但它只落在**跑 `build_forecast.py` 前的人工自检卡点**上：问四句话、靠作者自觉，没有字段登记、没有门禁拦截、没有脚本留痕。实战成品因此出现过：

- 全文 **0 个来源角标**、**0 个外链**；
- 「数据来源」框是一段纯文字，点不开；
- 来源栏只有机构名，无 URL、无页面标题、无抓取日期；
- 复用上一轮 `forecast_consensus.csv`，FY3 偏差 13.7%（§1.11-b 事故同源）。

「本轮联网」无法被证明，等于没做。本规范把它拆成三件可验收的东西：

| 层 | 载体 | 证明什么 |
|---|---|---|
| 数据层 | 六元组记录制（§二）、四级颗粒度（§三） | 每个数字有可取回的出处 |
| 留痕层 | `forecast_input.csv` / `content.json` 的 `source_meta` / `sources`（§五） | 本轮确实取过数、取的哪一类 |
| 门禁层 | `check_html.py` P0-13 / P1-7（§六）+ `verify_links.py`（§八） | 成品里真的带了链接、链接真的能打开 |

## 二、六元组记录制

每条进入报告的数据必须登记六个字段，**缺任一项不得写入报告**：

```
{ 数值, 口径说明, 来源URL, 页面标题, 发布日期, 抓取日期 }
```

- **数值**：带单位的具体数字。
- **口径说明**：分子分母口径、合并/母公司、当前预测 vs 上一个月预测、TTM/静态、币种、统计范围。
- **来源URL**：点开能直接找到该数字的页面（见 §三）。
- **页面标题**：便于 URL 失效后按标题回溯。
- **发布日期**：来源发布日；距抓取 > 1 年标 `[过时]`。
- **抓取日期**：本轮采集日期，时效性审计用。

**JSON 示例**（`sources` 中一条）：

```json
{
  "数值": "328.6 亿元",
  "口径说明": "东财 F10「当前预测」，8 家机构覆盖，合并报表口径，人民币；非「上一个月预测」",
  "来源URL": "https://emweb.eastmoney.com/PC_HSF10/ProfitForecast/Index?type=web&code=SH600900#forecast",
  "页面标题": "长江电力(600900) 盈利预测 — 东方财富 F10",
  "发布日期": "2026-11-06",
  "抓取日期": "2026-11-09"
}
```

**表格示例**（来源汇总区 `#src-summary` 六列）：

| 数值 | 口径说明 | 来源URL | 页面标题 | 发布日期 | 抓取日期 |
|---|---|---|---|---|---|
| 328.6 亿元 | 东财当前预测，8 家机构，合并口径 | `...ProfitForecast/Index?...#forecast` ↗ | 长江电力盈利预测 — 东财 F10 | 2026-11-06 | 2026-11-09 |
| 27.85 元 | 收盘价，2026-11-07 15:00，人民币 | `https://quote.eastmoney.com/sh600900.html` ↗ | 长江电力行情 — 东财 | 2026-11-07 | 2026-11-09 |

**L4 降级（无稳定 URL 时）**：走 `机构 · 《报告全名》 · 发布日期 · P页码`，并在 `#src-summary` 登记、标注「无公开链接」。

```
中国长江电力股份有限公司 · 《2025 年年度报告》 · 2026-04-30 · P142（无公开链接）
```

禁止裸机构名（「据东财」「据公司公告」）、禁止编造报告名或页码；查不到就如实降级，不硬凑链接。

## 三、可核查链接 · 四级颗粒度

**唯一验收标准**：点开链接后，能在该页面**直接找到被引用的那个数字**（Ctrl+F 可搜到，或在页面明示的图表/表格中）。做不到即不合格。

| 级别 | 要求 | 正例 | 反例 |
|---|---|---|---|
| **L1 页面级** | 带 `#锚点`，直达数字所在段 | `.../report-2026.html#revenue` | 机构官网首页 |
| **L2 文档级** | PDF/研报带页码锚点 | `.../annual-2025.pdf#page=142` | 只写「来源：XX 年报」 |
| **L3 查询级** | 带参数直达指标表 | `.../ProfitForecast/Index?type=web&code=SH600900#forecast` | 数据频道域名首页 |
| **L4 无链接** | §二降级署名 + 来源表登记 | `协会 · 《XX 年报》· 2026-03 · P8` | 裸机构名无出处 |

**纯域名首页不合格**：正则 `^https?://[^/]+/?$` 命中的 URL（如 `https://www.eastmoney.com/`）一律判为不可核查，必须补到 L1/L2/L3。锚点、页码、查询参数不是装饰，是「Ctrl+F 能搜到」的前提。

链接策略：权威源给官方披露页；研报/新闻给稳定摘要页；无稳定 URL 用 L4；报告末尾必须有 `id="src-summary"` 的「数据来源汇总」区，含全部六元组列，L4 项标「无公开链接」。

## 四、六类必须本轮联网核实的数据（财报分析特化）

> **总原则**：Phase 0 产出的本地 `output.csv`（+ `forecast_consensus.csv` 等辅助 CSV）是**主数据源**，联网核实是**交叉复核与新鲜度校验**，不是替代。禁止只吃本地不联网（新鲜度无法证明），也禁止拿联网片段覆盖主表数值（口径会打架）。联网只做三件事：核对量级、校验时点、补增量事件。

| # | 数据类 | 权威源建议 | 本轮核查动作 |
|---|---|---|---|
| ① | 一致预期 FY1/FY2/FY3 | 东方财富 F10「盈利预测」当前预测页、同花顺一致预期 | 取营收/归母净利/EPS；**必须取「当前预测」非「上一个月预测」**；记覆盖机构家数；`EPS × 总股本 ≈ 归母净利`（误差<2%）；旧 `forecast_*.csv` 一律视为未核验 |
| ② | 行情与估值时点 | 东财/同花顺行情页、交易所收盘数据 | 收盘价、总市值、PE/PB 记 `YYYY-MM-DD HH:MM`；标收盘/盘中、TTM/静态；Hero 写「数据截至」；与本地估值表对照量级 |
| ③ | 最新公告与增量事件 | 巨潮资讯 cninfo、上交所/深交所、公司官网 IR | 按公告日期核对是否为报告期后增量；按 §1.7 期次隔离（H1 与年报 YOY 分列）；状态精确到「已公告未实施 / 待股东会审议」 |
| ④ | 分红承诺与股东回报规划 | 巨潮公告、《未来三年股东回报规划》、年报「利润分配」章节 | 核对承诺期、现金分红比例下限、是否已实施；「已公告未实施」不得写成已落地（§1.8） |
| ⑤ | 同行可比公司同期指标 | 各公司年报/公告 + 东财 F10；≥2 家可比 | 同一报告期、同口径（合并/母公司一致）；逐家登记六元组；对手方数值同样经其 Phase 0 产出，勿手工估 |
| ⑥ | 宏观 / 行业口径 | 国家统计局、中电联、流域水文/来水公报、公司发电量公告 | 发电量、上网电价、来水偏丰枯等标统计口径、单位、发布日期；与公司口径（合并装机/上网电量）对齐，不用行业总量硬套公司数 |

六类的本轮勾选状态写进 `content.json` 的 `source_meta.online_checked`（§五），未勾选项不得在正文当作「已核实」表述。

## 五、取数留痕契约

**1. `forecast_input.csv` 增列**（在 §1.11-b 已有「来源 + 取数日期 + 覆盖机构家数」基础上补齐六元组）：

| 新增列 | 填什么 | 谁填 |
|---|---|---|
| `来源URL` | L1/L3 直达页，如东财 F10 盈利预测页带 `#forecast` | 报告作者（联网取数时） |
| `抓取日期` | 本轮 `YYYY-MM-DD` | 报告作者 |
| `口径` | 含 `权威主源` / `单券商旁证`、当前预测、合并口径、币种 | 报告作者；`build_forecast.py` 据此判主源 |

**2. `content.json` 必须提供 `source_meta`**：

```json
{
  "source_meta": {
    "fetched_at": "2026-11-09 14:30",
    "tier": "RICH",
    "online_checked": {
      "consensus": true,
      "quotes_valuation": true,
      "latest_filings": true,
      "dividend_plan": true,
      "peer_metrics": true,
      "macro_industry": false
    }
  },
  "sources": {
    "forecast_consensus_em": {
      "url": "https://emweb.eastmoney.com/PC_HSF10/ProfitForecast/Index?type=web&code=SH600900#forecast",
      "fetched_at": "2026-11-09 14:30"
    },
    "quote_close": {
      "url": "https://quote.eastmoney.com/sh600900.html",
      "fetched_at": "2026-11-09 14:30"
    }
  }
}
```

- `sources` 里**必须有一条 key 含 `forecast` 或 `consensus`**，且该条带 `url` + `fetched_at`；这是「一致预期本轮联网」的最小机读证据。
- `online_checked` 六项对应 §四六类；`false` 项正文不得声称已核实。
- `tier` 沿用 §1.4 可信度分级与 LEAN/RICH 模式。

**3. 谁产出、谁填写**：

| 内容 | 产出方 |
|---|---|
| `forecast_consensus.csv` / `forecast_discrete.csv` 数值、主源 vs 单券商判定、来源日期 > 30 天新鲜度告警 | `build_forecast.py`（脚本，机读） |
| 六元组里的 `来源URL` / `页面标题` / `抓取日期` / `口径说明`、`source_meta`、`sources`、正文 ↗ 角标、`#src-summary` 来源汇总区、L4 降级署名 | **报告作者**（人工，联网取数时填） |

脚本无法替作者联网，只能校验作者填了什么；把留痕责任推给脚本等于留空。

## 六、门禁映射表（`scripts/check_html.py`）

| 门禁 | 状态 | 校验点 | 对应本规范 |
|---|---|---|---|
| **P0-3** 远程资源 | 已有，v2.1.4 收口 | `<script>/<link>/<img>` 的 `http(s)` `src` 仍一律禁；**来源角标白名单放行**：正文 `<a href="http(s)://…">↗</a>` 指向数据披露页不误杀 | §三、§七.4；避免「为可核查加外链」反被零远程门禁拦死 |
| **P0-13** 来源可核查 | **新增** | ① `id="src-summary"` 锚点在位 ② 正文 ↗ 角标数 ≥ 阈值（每处引数有角标）③ 独立域名 ≥ 2 ④ 非纯域名（拒 `^https?://[^/]+/?$`）⑤ 来源汇总是六列六元组 ⑥ 有取数/抓取日期列 ⑦ 所有角标 URL 均登记在 `sources`/汇总区（无悬空）⑧ 🥇🥈🥉 已转「公告/接口/旁证」文字徽章并带在线核实状态 | §二、§三、§五；**纯 HTML 静态检查，离线可跑，不依赖网络** |
| **P1-5** Hero 数据截止 | 已有 | Hero 含 `YYYY-MM-DD [HH:MM]` 及「数据截至/截止/数据时点」 | §四②；混用多时点须在 `#src-summary` 逐条标注 |
| **P1-7** UNSOURCED 悬空 | **新增** | 正文出现 `UNSOURCED` 占位、或数字既无 ↗ 角标又未在 `sources` 登记时告警；禁止悬空来源残留 | §二、§五 |

> 分工红线：`check_html.py` 的门禁**必须离线可跑**，只做静态结构校验；链接能否打开由 `scripts/verify_links.py` 单独跑网络验活，二者不互相依赖（见 §八）。

## 七、常见坑

1. **HEAD 404 / GET 200 不能误报坏链**：部分站点（如 yofc.com）对 HEAD 或自定义 UA 返 404，GET 正常。`probe()` 在 HEAD 返 4xx/5xx 时用 `GET + Range: bytes=0-0` 复核，以 GET 为准；只信 HEAD 会把好链删掉。
2. **`&amp;` 必须还原成 `&`**：HTML 里带查询参数的 URL 写成 `...&amp;code=SH600900`，直接拿去探活会打错地址。`collect()` 用 `html.unescape()` 还原后再去重、再探活。
3. **补链脚本必须跳过 `<script>` / `<style>` / HTML 注释**：内联 Chart.js 里有字符串常量，`<!-- ... -->` 里有示例 URL，`<style>` 里可能有 `url(...)`；不跳过会把它们当来源链接补角标、误探活、误计数。
4. **角标图标用 `↗`（U+2197），不用 emoji**：P1-1 的 `EMOJI_RE` 拦截 `\U0001F300-\U0001FAFF` 与 `\u2600-\u27BF`，🔗/📎/📄 会被判 emoji；`↗` 属 Arrows 块，安全。同时 §1.8.1 禁机械标签，角标只挂图标不写「🔗数据来源」。
5. **来源汇总区不能用 `div.step-card`**：P0-7 硬编码数 `<div class="step-card" id="stepN">` 恰好 9 个，多一个就数到 10 触发 P0 阻断。用 `<section id="src-summary">` 或普通 `<div>`，别复用 step-card 类名。
6. **403/405/429 与超时计 skip 不计 dead**：站点拒绝探活、环境网络问题是「没验成」，不是「链接坏了」，不能据此删链。

## 八、验活 ≠ 可核查（边界声明）

`scripts/verify_links.py` 只判断**链接能否打开**（HEAD/GET 状态码），**不判断页面里是否真有被引的那个数字**：

- 打开成功 = 可访问，不等于 Ctrl+F 搜得到 328.6 亿元；
- 后者必须按 §三四级颗粒度**人工抽查**（L1 锚点是否对准段落、L2 页码是否含该表、L3 参数是否落在指标行、L4 署名是否可回溯）；
- 验活通过不能作为 P0-13「可核查」的充分条件，P0-13 判的是链接形态与登记完整性，人工抽查判的是内容命中。

因此发布顺序是：`check_html.py`（离线静态门禁）→ `verify_links.py --strict`（网络可达）→ 抽查若干角标链接确认数字在页（人工）。三步都过，才算「来源可核查」。
